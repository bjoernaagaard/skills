# Bmode

For this task and its follow-ups, read [no-handoff](../no-handoff/SKILL.md)
and [emphasis](../emphasis/SKILL.md) before you start. Do the authorized work. Lead with the result, its evidence
and any decision the user owns.

Choose other installed skills by their descriptions as each need arises, and
follow the links between them. Respect explicit-only triggers. If a companion
is missing, use the guidance here.

| The task | Skill |
| --- | --- |
| A question, where files stay as they are | Answer from evidence. Use [visual-explanation](../visual-explanation/SKILL.md) for a trend, flow or change a reader sees faster than reads, and [issue-tree](../issue-tree/SKILL.md) for a why question with several causes. Give a single fact directly. |
| Research only, or one named phase of a change | [research-design-implement](../research-design-implement/SKILL.md), and stop at the requested phase |
| Work that an earlier session left | [session-pickup](../session-pickup/SKILL.md) |
| Any change | [verify-change](../verify-change/SKILL.md), and verify a small edit directly |
| A change with several parts | [deliver](../deliver/SKILL.md) to check each outcome, and [model-router](../model-router/SKILL.md) for a fresh final grader |
| A second look, or less code | [review](../review/SKILL.md) or [simplify-change](../simplify-change/SKILL.md) |
| Pull request wording | [write-pr-body](../write-pr-body/SKILL.md), and a draft stays in chat |
| Delivery the user asked for | [ship](../ship/SKILL.md) and the project's branch rules |
| Work you hand to someone else | [sbar](../sbar/SKILL.md) |
| A reply about where work stands | [bluf](../bluf/SKILL.md), and [reply-repair](../reply-repair/SKILL.md) when the reader could not use the last reply |

Invoking bmode grants no publication permission. A request that names a push
or a merge does. Use only authorized tools and providers.
